## 冯诺依曼结构
在冯·诺依曼结构诞生之前，人类对自动计算的追求早已开始。从巴贝奇的差分机与分析机，到二战期间用于计算火炮弹道的机电式计算机，如美国的Harvard Mark I，这些早期的“巨人”展现了自动计算的潜力，但也暴露了巨大的局限性。

其中最核心的问题在于“程序”与“数据”的分离。以ENIAC这台公认的世界上第一台通用电子计算机为例，它是一个由约18000个真空管组成的庞然大物。它的计算能力是革命性的，但为其“编程”却是一场噩梦。程序员需要通过手动插拔成千上万的电缆、设置无数的开关来配置计算流程。这意味着，**每执行一个新的算法逻辑，就需要耗费数天甚至数周的时间进行物理上的重新布线**。也就是说，ENIAC是一台“硬件编程”的计算机，其程序是硬连接在机器结构之中的，缺乏我们如今视为理所当然的灵活性。

冯诺依曼结构的革命性和创新性，并不在于它发明了计算机的某个部件，而在于它提出了一种全新的组织思想，核心可以归结为两大基本原则
* 存储程序：最根本、最核心的原则，计算机的程序指令和需要处理的处理，以二进制形式一同存放在同一个存储器中。这意味着，程序本身可以被当做数据来对待，即它可以被修改、被其他程序生成，甚至在运行时自我更新。
* 顺序执行：计算机在控制器的指挥下，自动地，顺序地从存储器中取出指令并执行，除非遇到跳转指令，否则计算机会按照指令在存储器中存放的地址顺序，一条接一条的执行下去。

在现在看来，这两点看似简单且理所当然，但在当时，它却带来了翻天覆地的变化。它使得计算机的“通用性”成为现实。**同一台硬件机器，通过加载不同的程序，就能完成科学计算、文字处理、图形渲染等完全不同的任务。程序员不再需要重新布线电缆和开关，他们只需将编写好的程序输入计算机，剩下的工作便由机器自动完成**。这极大地提升了编程效率，并使得软件产业从硬件中分离出来，成为一个独立发展的领域。

当然，除了两个最核心的基本原则之外，冯·诺依曼还定义了计算机的基本结构，他将计算机定义为由五大部件组成的系统，这五大部件各司其职，通过紧密的协作完成复杂的计算任务。
- 运算器（Arithmetic Logic Unit, ALU）：也叫做算术逻辑单元，负责执行所有的算术运算（加、减、乘、除）、逻辑运算（与、或、非、异或）及其他运算。控制器从内存中获取到的指令，交由ALU来执行。ALU功能高度独立，是解耦和模块化设计在硬件中的很好的体现。
- 控制器（Control Unit, CU）：控制器是计算机的“指挥中心”。它不执行任何实际的计算，但其作用至关重要。控制器负责解读当前正在执行的指令，并根据指令的含义，向计算机的其他所有部件（运算器、存储器、输入/输出设备）发出精确的控制信号，协调它们步调一致地工作。例如，它告诉存储器“现在要读/写哪个地址”，告诉运算器“现在要进行加法还是乘法运算”，告诉输入设备“准备接收数据”。控制器和运算器合在一起，构成了我们今天所说的中央处理器（CPU）的核心。
- 存储器（Memory）：存储器用于存放程序（指令序列）和数据。在冯·诺依曼的原始构想中，它指的是主存储器（内存）。内存被组织成一系列线性排列的存储单元，每个单元有一个唯一的地址，并可以存储一定数量的二进制代码。程序指令和数据通过地址来寻址。
- 输入设备（Input Device）：是计算机与外界沟通的耳朵和眼睛，负责将外部的信息（程序和数据）转换成计算机能够理解和处理的二进制形式，并送入存储器。键盘、鼠标、扫描仪、触摸屏等，都是典型的输入设备
- 输出设备（Output Device）：是计算机的嘴巴和手，将计算机处理后的二进制数据结构，转换成人或其他设备能够理解的形式（如文字、图像、声音）并呈现出来。显示器、打印机、音响等都属于输出设备。

冯诺依曼结构的提出，是计算机科学史上的里程碑，使得计算机的设计实现了标准化和模块化，不同厂商可以依据同一套架构来设计和制造兼容的硬件，这极大的推动了计算机产业的工业化进程，不仅如此，还确立了软件的重要地位，使得编程称为一门独立的学科。

然而，这一经典结构也存在着其固有的瓶颈，最著名的便是“冯·诺依曼瓶颈”。

瓶颈的核心在于：在传统的冯·诺依曼结构中，指令流和数据流共享同一条通往存储器的总线。这意味着，在同一个时钟周期内，CPU要么在取指令，要么在存取数据，无法同时进行。随着CPU速度的飞速提升，其处理能力远远超过了存储器（内存）的供给速度。CPU常常需要“等待”数据从相对缓慢的内存中读取或写入，这种等待严重制约了整体性能的发挥。这就好比拥有一个超级发动机（CPU），却只配了一根细小的油管（系统总线），发动机的动力因供油不足而无法完全释放。

为了突破这一瓶颈，计算机架构师们提出了诸多创新性的改进方案：
- 存储器层次结构： 通过在CPU和主存之间加入高速缓存（Cache），利用程序的局部性原理，将最常用的指令和数据存放在速度极快的Cache中，大幅减少CPU访问慢速主存的次数。这是现代计算机系统中最为关键和有效的优化手段之一。
- 哈佛结构： 这是一个对经典冯氏结构的修正。其核心思想是将指令存储器和数据存储器在物理上分开，并为之提供独立的总线。这样，CPU可以同时读取一条指令和存取一个数据，从而极大地提升了并行性和执行速度。现代处理器虽然整体上仍是冯·诺依曼结构，但在CPU内部（尤其是Cache层面），普遍采用了哈佛或类似哈佛的改进结构（如CPU的L1 Cache分割为指令Cache和数据Cache）。
- 并行处理技术： 通过引入多核处理器、指令级并行（流水线、超标量）、线程级并行等技术，让计算机在同一时间处理多条指令，从而在宏观上掩盖了瓶颈带来的延迟。

## CPU工作原理
冯诺依曼的存储程序思想带来了一个根本性的转变：既然程序可以像数据一样存储，那么执行程序的部件就可以被标准化、通用化。我们不需要为每个新问题重新设计一台机器，只需要设计一个能够理解并执行基本指令集的通用处理核心。这个核心就是CPU概念的雏形。

根据冯诺依曼结构，CPU通过三条主要的高速公路与内存连接
* 地址总线：一条单向的高速公路，由CPU发出，当CPU需要从内存读取指令或数据，或者向内存写入数据时，它通过这条总线告诉内存，我要访问哪个地址。
* 数据总线：一条双向的高速公路，它负责在CPU和内存之间运送实际的货物，即从内存读出的指令或数据，或者CPU要写入内存的数据。
* 控制总线：一条传递管理信号的公路，CPU通过它向内存等其他部件发送命令，如读或写，而其他部件也可以通过它向CPU发送中断等请求。

CPU主要由运算器、控制器、寄存器组成。对于寄存器来说，有两个比较特殊的，用于控制器取指和译码用的，那就是IP指令指针和IR指令寄存器。IP用来存储下一条指令所在的内存地址（IP是x86的寄存器，更加通用的名称是程序计数器 PC Program Counter），IR用于存储当前指令。

CPU工作本质是一个永不停歇的循环，这个循环被称为指令周期。主要分为五阶段：取指、译码、执行、访存、回写。

1. 取指阶段

控制器中的程序计数器（PC）寄存器，保存着下一条指令的地址。
- 第一步： 控制器将PC中的地址通过地址总线发送给内存。
- 第二步： 控制器通过控制总线向内存发送一个“读”信号。
- 第三步： 内存接到地址和读命令后，从对应位置取出指令，通过数据总线送回CPU。
- 第四步： CPU将收到的指令存入指令寄存器（IR）中。
- 第五步： 与此同时，程序计数器（PC）自动增加一个步长（根据一条指令所占的内存大小而定），存储下一条指令的地址，为下一个取指周期做好准备。

至此，CPU成功拿到了当前要执行的“任务书”。

2. 译码阶段

指令寄存器（IR）中存放的是一条由0和1组成的二进制编码。控制器中的指令译码器会分析出这条指令要求进行什么操作（是加法？是比较？还是跳转？），以及操作数在哪里。
例如，一条加法指令会被译码为：“从寄存器A和寄存器B中取出两个数，送到ALU执行加法操作，然后将结果存回寄存器A”。

然后，会对应产生一组使能信号，使能信号控制CPU中对应的部件工作。

3. 执行阶段

控制器根据译码结果，向相关的部件发出控制信号，执行指令所要求的操作。执行的操作类型繁多，我们列举一些。其实，这就是我们在指令系统那部分讲到的CPU基础指令。
- 数据传送： 例如，将数据从内存加载到寄存器，或将寄存器中的数据存回内存。控制器会指挥寄存器、数据总线和内存控制器协同完成拷贝任务。
- 算术/逻辑运算： 控制器将操作数从寄存器送入ALU，并告知ALU执行何种运算（如加法）。ALU进行计算并产生结果和相关的状态信息（如结果是否为零、是否溢出等），这些状态会被记录在状态寄存器中。
- 控制流操作： 最常见的是“跳转”指令。例如，在判断两个数值后，程序可能需要跳过一些指令，转到另一个地方执行。执行这类指令时，控制器会修改程序计数器（PC）的值，将其设置为跳转目标地址，从而改变指令的正常执行顺序。循环和条件判断（if-else）都是通过此类指令实现的。

4. 访存阶段

只有那些需要访问数据存储器的指令（如加载 Load、存储 Store）才会在本阶段进行操作。其他类型的指令通常会“跳过”这个阶段，或者在此阶段不做任何事。
在五阶段模型中，“执行”阶段被严格定义为在算术逻辑单元（ALU）中进行的计算操作（如加减乘除、逻辑运算等），而访问数据存储器的操作被独立出来，成为一个专门的“访存”阶段。在四阶段模型中，“执行”是一个更宽泛的概念，它可能包含了ALU计算和存储器访问。

5. 回写阶段

将执行阶段产生的结果（如ALU的计算结果）写入到指定的目的地，通常是一个CPU内部的寄存器，或者是存储器中的某个单元。对于运算指令，结果通常会被写回到某个通用寄存器中（如累加器ACC），对于存储指令，结果则会被写入内存。
当然，并不是每条指令在每个阶段都有事可做。我们举几个例子。

```
1. 算术指令 ADD R1, R2, R3
取指 → 译码 → 执行(计算R2+R3) → [访存：无操作] → 回写(结果→R1)

2. 加载指令 LOAD R1, [地址]
取指 → 译码 → 执行(计算地址) → 访存(从内存读数据) → 回写(数据→R1)

3. 存储指令 STORE R1, [地址]
取指 → 译码 → 执行(计算地址) → 访存(将R1数据写入内存) → [回写：无操作]
```

## CPU的性能指标
对CPU来说，它的时钟频率就叫做主频，它就像是CPU的心跳，或者说指挥CPU电路同步工作的节拍器。每一个时钟周期滴答一次，CPU就完成一个最基本的操作。因此粗略的说，主频越高，单位时间内CPU能够执行的动作就越多，处理速度自然就越快，常说的 3.0Hz,5.0Hz 意味着每秒由30亿或50亿个时钟周期。

那么如何提高主频呢？

我们知道，时钟周期的大小由整个电路中执行最慢的那一段组合逻辑来决定，我们称之为关键路径。时钟周期必须大于等于关键路径的执行时间，也就是从输入到达这个组合电路到输出最后稳定的延迟时间，这样才能保证当时钟下一个边沿到来时，下一个组合逻辑的输入数据都已经稳定、可靠的准备好。

假设原来关键路径需要1纳秒完成计算，我们设定时钟周期为1.2纳秒。现在，通过提高芯片的制造工艺（如从14nm到10nm），或者提高工作电压，晶体管的开关速度变得更快，组合逻辑的传播延迟降低了。现在关键路径只需要0.8纳秒。那么，我们就可以安全地将时钟周期缩短到1.0纳秒，这意味着时钟频率从约833 MHz（1/1.2ns）提升到了1.0 GHz（1/1.0ns）。

不过，主频的提高是有极限的。因为晶体管的开关速度是有极限的，而且更快的开关速度意味着需要更大的电压支持，带来更大的动态功耗（CV²f，这里的C代表芯片内部的电容负载，V是工作电压，f是时钟频率）。当主频被推向极致，其带来的功耗和热量呈指数级增长。奔腾4 NetBurst架构为了冲击更高频率，设计了超长的流水线，但随之而来的是恐怖的发热量，一个小小的CPU表面甚至可以达到核电站级别的功率密度，普通的风冷散热已难以为继。

最终，我们撞上了由半导体物理和热力学定律共同筑起的“频率墙”，为这场疯狂的主频之争划上了休止符，“主频至上”的时代由此落幕。这也就是为什么，在过去的十余年里，**CPU的最高频率始终在4-6 GHz的区间内徘徊，难以突破的原因**。

至此，行业的共识发生了根本性的转变：从一味追求“更快的心跳”，转向了如何让CPU“更聪明地工作”。**于是，发展的重心转向了多核架构**。既然一颗CPU的心脏跳得太快会“心力衰竭”，那么为什么不给它装上两颗、四颗，甚至更多颗心脏呢？让这些核心协同工作，同时处理多个任务，这就是并行计算的思想。多核技术在不显著提高单核主频的情况下，极大地提升了CPU的整体数据处理能力，这对于多任务操作系统和高度并行的服务器应用（如网页服务、科学计算）带来了立竿见影的性能提升。从此，我们进入了“核战争”的时代，主频，这个曾经的王者，退位成为衡量CPU性能的众多重要指标之一，而非唯一标准。

升频降频：现代CPU关于主频概念已经变得非常动态和复杂，远不是一个单一的数字。比如 i9-14900K 处理器你会看到
* 性能核（P-core）基础频率 3.2GHz
* 性能核（P-core）最大频率 高达6.0GHz
* 能效核（E-core）基础频率 2.4GHz
* 能效核（E-core）最高频率 高达4.4GHz

升频不是没有代价的，晶体管开关的更快，能量消耗急剧增加，产生大量热量，你会明显感觉手机或电脑后背变热，风扇开始疯狂工作，电量具体下降。除此之外，系统稳定性具体下降，如果速度提升的太快，组合逻辑电路可能无法在缩短的周期内完成计算，**当第二个时钟边沿来临时，数据还没有准备好，就会导致计算错误或系统崩溃（也就是死机、蓝屏）**。

有升频就有降频，为了节省功耗和减少发热，当你的手机只是在待机，或者你只是在阅读文档这种轻量级任务时，完全不需要让CPU全速运转，降低频率可以大幅降低能耗、延长电池续航，并让设备保持凉爽。

CPU的功耗有两部分构成
* 动态功耗：CPU在活动时消耗的能量，主要发生在晶体管开关状态切换的瞬间。其核心就是公式 P_dynamic=CV²f。C代表芯片内部的电容负载，V是工作电压，f是时钟频率。为了降低功耗，工程师们以方便通过改进制造工艺来减少C，另一方面致力于不断降低CPU的工作电压V。这也是为什么更先进的制程如此重要，因为它们通常能在更低的电压下运行，并拥有更小的电容，从而显著降低动态功耗。
* 静态功耗：即使CPU什么都不做，只要它通着电，就会消耗能量，这就是静态功耗。它主要由晶体管的漏电流引起。在当今的纳米级制程下，晶体管如此之小，以至于即使处于关闭状态，也会有微弱的电流从源极“泄漏”到漏极，如同一个关不紧的水龙头。制程越先进，晶体管尺寸越小，控制漏电流的挑战就越大。静态功耗与频率无关，但与温度密切相关，温度越高，漏电流越严重。

正是这两种功耗的共同作用，决定了CPU的总功耗和发热水平。**当主频飙升时，动态功耗线性增长；而为了支撑高频率，电压往往也需要提高，导致动态功耗以平方关系暴增，同时高温又加剧了静态功耗，形成一个正反馈的恶性循环，最终导致散热系统崩溃**。

而对功耗的重视，在移动互联网时代被提到了前所未有的战略高度。在智能手机、平板电脑、笔记本电脑等移动设备中，电池容量是极其有限的宝贵资源。一颗功耗控制出色的CPU，意味着更长的续航时间、更低的发热（从而保证性能持续稳定输出，避免因过热降频），以及更轻薄的产品设计。

因此，移动设备芯片（如ARM架构的处理器）从设计之初就将“能效比”作为核心指标。它们不再单纯追求峰值性能，而是力求在每一瓦特的功耗下，挤出尽可能多的计算能力。这种设计哲学与传统桌面CPU形成了鲜明对比，**也推动了如大小核架构的兴起：将高性能核心（大核）处理繁重任务，与高能效核心（小核）处理日常后台任务相结合，系统根据负载智能调度，实现性能与功耗的完美平衡**。

这种对功耗的极致追求，如今也影响到数据中心和桌面计算领域。数据中心的运营成本中，电费占据了巨大比重，低功耗、高能效的CPU直接意味着成本节约和环保效益。在个人电脑上，我们也看到了能效核的引入，在上述英特尔酷睿i9-14900K处理器的介绍中就有性能核和能效核的区别，使得CPU在保持多线程性能的同时，在低负载下更加安静、凉爽。

## CPU指令流水
单纯提升了主频面临着物理极限和功耗墙的巨大挑战。那是否存在另一种方法，在不显著提高主频的前提下，让CPU在单位时间内完成更多的工作呢？

计算机科学家从工业生产中获得灵感，设计出了一项堪称CPU发展史上里程碑的技术：指令流水线。它让CPU内部的各个部件从轮流工作变为同时工作，极大的挖掘了CPU的性能潜力。

没有流水线时，CPU顺序执行：取指、译码、执行、访存、写回，在顺序执行模型中，CPU在指令一条执行时，必须完整的经历以上所有阶段后，才会开始处理下一条指令。

指令流水线的思想，正是借鉴了工业上的装配流水线。它将指令的完整执行过程，划分为若干个耗时基本相等的子过程，每个阶段由一个独立的硬件功能部件来完成，这样多条指令就以在时间上重叠执行。

当然，五级流水线只是一个教学模型。为了追求极致的性能，现代处理器的流水线的层级很深，可能长达10-20级，甚至更多。例如，它将“取指”进一步分解为“预取”、“地址转换”等，将“译码”分解为若干级（因为x86指令非常复杂），将“执行”分解为更多的功能单元，这就是超流水线技术。

超流水线通过将每一级流水线进一步细分成更小的、更简单的步骤，使得每个步骤可以在更高的时钟频率下完成。这使得CPU的主频得以大幅提升。然而，事物总有两面性。更深的流水线也带来了新的问题：
- 惩罚更重： 一旦发生分支预测错误，需要清空的流水线级数更多，性能损失更大。
- 功耗更高： 更多的流水线寄存器（流水线上的不同阶段对应不同电路，相邻的电路之间需要通过流水线寄存器来同步数据）意味着更多的晶体管开关，导致动态功耗增加。
- 复杂性剧增： 管理如此深的流水线，解决各种冒险的硬件逻辑变得极其复杂。

Pentium 4的指令流水深度达到31级，但是，最终因其高功耗和低“每时钟周期性能”而饱受诟病，这也让业界认识到，流水线的深度并非越深越好，需要在频率、吞吐率、功耗和复杂度之间寻求一个精妙的平衡。后来的CPU架构回归了相对较短的流水线，但通过超标量架构和更智能的乱序执行引擎，实现了更高的能效比。

超标量架构是另一种提升指令级并行性的关键技术。与超流水线主要通过增加流水线深度来提高时钟频率不同，超标量架构侧重于在同一个时钟周期内同时发射并执行多条指令。简单来说，超标量处理器内部包含了多个功能单元（如多个算术逻辑单元ALU、加载/存储单元、分支单元等），并配备了复杂的指令调度逻辑，能够从指令流中动态地识别出可以并行执行的指令，并将它们分发到不同的执行单元上。

例如，在一个典型的超标量处理器中，可能每个周期可以同时取指和译码多条指令，然后通过一个称为“发射队列”的机制，判断指令之间的依赖性。如果两条指令没有数据依赖或结构冲突，它们就可以被同时送到不同的执行单元执行。这样，理想情况下，一个k路超标量处理器（每个周期发射k条指令）的峰值吞吐率可以达到顺序执行模型的k倍。

**超标量架构与超流水线并不互斥，而是经常结合使用**。现代高性能处理器（如Intel的Core系列或AMD的Ryzen系列）通常都是“超标量超流水线”设计：既通过超流水线提高主频，又通过超标量结构提高每个周期的指令吞吐率。这种结合使得处理器能够在高时钟频率下同时处理多条指令，从而大幅提升整体性能。

## CPU vs GPU
GPU的诞生源于一个看似简单却计算密集的需求：图形渲染。在20世纪90年代，随着图形用户界面和3D游戏的兴起，传统的CPU在处理大量图形数据时显得力不从心。**图形渲染本质上是对数百万个像素执行相同的操作，这种高度并行的特性催生了专门的图形处理硬件**。

1999年，NVIDIA率先提出“GPU”这一术语，标志着图形处理器作为一个独立产品类别的诞生。关键的转折点出现在2007年，当NVIDIA推出**CUDA（Compute Unified Device Architecture）**编程平台时，GPU首次向软件开发者敞开了通用计算的大门，允许通过软件编程的方式调用GPU工作。这时的GPU已经不再是单纯的图形加速器，而是进化为能够处理各种数据并行任务的通用并行计算处理器。

要理解GPU的强大能力，我们需要深入探究其与众不同的架构设计。与CPU追求单线程性能最大化的设计哲学不同，GPU选择了截然不同的道路：通过大规模并行来获得极高的吞吐量。

CPU，常被称为计算机的“大脑”，是通用计算的核心。它专注于执行复杂逻辑和控制任务，像一位学识渊博的教授，能够处理各种复杂问题。CPU的设计目标是尽可能快地完成单个任务，强调低延迟和顺序执行效率。无论是操作系统的运行、数据库查询还是应用程序的执行，CPU都是不可或缺的核心。

GPU则走了一条不同的道路。最初，GPU只是为了处理图形渲染而设计的专用芯片。在游戏和多媒体应用需求的驱动下，GPU逐渐演化出能够同时处理数百万个像素的架构。它不像CPU那样追求单个任务的完成速度，而是专注于同时处理大量简单任务，强调的是高吞吐量而非低延迟。

这种设计目标的差异直接体现在硬件架构上。**CPU通常只有几个到几十个强大的核心，每个核心都能够独立处理复杂的任务；而GPU则拥有数千乃至上万个相对简单的核心**，比如，NVIDIA的GA102 GPU（用于RTX 3090）总计10496个CUDA核心，这些核心协同工作，以并行的方式处理海量数据。

GPU的内存架构同样体现了并行优先的设计理念。与CPU复杂的多级缓存层次不同，GPU采用了高带宽内存子系统，包括显存和共享内存。这种设计使得GPU能够同时为数千个线程提供数据，虽然单个线程的访问延迟较高，但整体吞吐量却远超CPU。

控制逻辑的简化是GPU架构的另一个关键特点。CPU将大量晶体管用于复杂的控制逻辑，如分支预测、乱序执行等，以优化单线程性能。相比之下，**GPU的控制逻辑相对简单，将更多晶体管资源用于算术逻辑单元（ALU），这使得它在纯计算任务上具有显著优势**。

对于CPU，重要的性能指标包括：主频、缓存大小、指令级并行度等。CPU性能评估关注的是任务完成的延迟，即一个任务从开始到结束需要多长时间。

对于GPU，关键性能则大不相同：吞吐量（如FLOPS，即每秒浮点运算次数）、内存带宽、线程并行度、执行单元利用率等。GPU性能评估则更关注单位时间内能够完成多少工作，而非单个任务的完成速度。

GPU编程需要开发者采用不同的思维模式，即从顺序执行转向大规模并行。

CUDA平台的推出是GPU计算发展的重要里程碑。它首次为开发者提供了直接利用GPU进行通用计算的能力，CUDA扩展了C/C++语言，引入了核函数、线程层级结构、共享内存等概念，使开发者能够惊喜控制GPU的并行计算资源。

**紧随其后的是OpenCL，这是一个开放的、跨平台的并行编程框架**。与CUDA主要针对NVIDIA硬件不同，OpenCL支持多种处理器架构，包括AMD GPU、Intel处理器等，为异构计算（CPU负责准备数据、管理任务流程和处理复杂逻辑，然后将适合并行的计算任务交给GPU执行）提供了更广泛的解决方案。

现代GPU编程已经发展到更高层次的抽象。**诸如TensorFlow、PyTorch等深度学习框架，以及OpenACC、Kokkos等并行编程模型**，使得开发者能够在不必深入了解硬件细节的情况下充分利用GPU的计算能力。这种发展趋势极大地降低了GPU编程的门槛，推动了GPU计算的普及。

## CPU指令集
从简单整数加法到复杂的浮点运算，从内存读写到条件判断。每一种操作，都需要一个独一无二的二进制编码来控制。所有这些二进制编码的集合，就构成了CPU的指令集。

我们希望CPU具有什么样的功能，就要设计相应的硬件电路，然后定义对应的指令来控制电路。在没有高级编程语言出现的时代，早期程序员就通过编写一条一条的CPU指令（二进制串）来控制CPU执行想要的运算。

早期计算机能支持的功能是有限的，因此电路也不会像如今这样复杂，相应的指令集也很小。以1949年诞生的第一台通用电子计算机为例，他的指令集只有18条，涵盖最基础的内存访问、算术运算和程序控制转移。

随着半导体技术的飞速发展，计算机应用场景爆炸式增长，指令集也随之进入百花齐放的时代。不同厂商、不同型号的CPU，其指令集千差万别，即便是两数相加这样的基本操作，在不同类型的处理器上，对应的二进制编码也可能完全不同。

指令集是CPU唯一能直接听懂的语言，我们使用高级编程语言编写的所有程序，最终都必须通过编译器这个翻译官，转换成一条条由指令集中的指令组成的序列，才能交由CPU一条一条的执行。如果不同类型的CPU芯片，它们的指令集完全不同，那么高级语言就必须为不同CPU开发不同的编译器，否则程序无法运行。

为了打破这种束缚，指令集架构（Instruction Set Architecture，ISA）的概念被提出。ISA是一套抽象的模型和规范，它定义了CPU所支持的基本指令、数据类型、寄存器、寻址方式以及内存访问模型等。简单来说，ISA是CPU的“行为说明书”。任何遵循同一份ISA规范设计和制造的CPU，无论其内部实现技术（比如电路怎么设计）如何不同，都能运行相同的软件。这使得软件和硬件得以解耦，不依赖特定硬件，软件的开发变得简单。

在激烈的市场竞争和技术演进中，一些ISA因其卓越的设计和成功的商业策略脱颖而出，成为主流。时至今日，**有两个指令集架构在全球计算领域占据着绝对的统治地位：x86与ARM**。接下来，我们依次简单介绍它们。

大多数PC计算机和服务器使用的CPU都基于x86指令集，x86名称源于英特尔早期处理器的命名传统。1978年英特尔发布首款16位微处理器8086，标志着x86架构的诞生。

随着CPU芯片的迭代升级，不断有新的指令添加到x86指令集中，从最初8086的不到百条指令，逐步演进到如今的数千条指令。不过在演进的过程中，开发团队始终强调指令集的向后兼容性，以确保旧型号CPU上编写的软件能在新的CPU上运行。

值得注意的是，虽然x86指令集架构是英特尔公司创造的，但是，使用这一指令集设计CPU的公司不止英特尔，还有很多其他处理器芯片设计和生产公司，其中最出名的一个是AMD公司。而且，更有趣的是，率先将x86指令集架构扩展到了兼容64位CPU的是AMD而非英特尔。

当时，英特尔将重心放在了与惠普联合开发的全新64位架构IA-64，该架构不兼容原有的x86指令集，现在看来，当时纯属是决策失误。于是，AMD就抓住了这一机遇，对x86指令集进行扩展，设计出了支持64位CPU的AMD64，并生产了基于AMD64的首款64位处理器：Opteron和Athlon 64。AMD64架构因其出色的性能和良好的兼容性迅速获得市场认可。英特尔随后也被迫采用了这一架构，推出了与之兼容的64位处理器。如今，兼容64位CPU的x86架构通常被称为x64或x86-64，它已成为个人计算机和服务器领域的主流。

与x86在个人计算机和服务器领域的通知地位不同，ARM指令集架构凭借其低功耗、低成本和高能效的特性，主导了智能手机、平板电脑以及嵌入式设备市场，在这些市场占据了超过90%的份额。

ARM架构起源于1985年，当时英国的Acorn计算机公司为了摆脱对外部处理器供应商的依赖，由Roger Wilson和Steve Furber带领团队设计了第一款32位的RISC处理器（关于RISC下一节会讲到），并将其命名为ARM（Acorn RISC Machine）。

ARM公司（1990年由Acorn改组而成）采用了一种独特的商业模式：它本身并不生产和销售芯片，而是通过授权其处理器架构设计给其他公司（如苹果、高通、三星等），由这些公司基于ARM架构设计并生产自己的处理器。

ARM处理器通常以片上系统（SoC）的形式存在，将CPU、内存控制器、图形处理器等集成于单一芯片，特别适合对功耗和尺寸极为敏感的移动设备。因此，它毫无悬念地主宰了智能手机和平板电脑的世界。ARM架构也从32位演进到64位，并且其影响力正不断向PC和服务器领域扩张。

一个标志性事件是，**苹果公司在2020年宣布将其Mac计算机产品线从x86架构，迁移到自研的基于ARM架构的芯片上**，现在，苹果的M系列Mac电脑使用的芯片就是基于ARM架构设计的，这进一步证明了ARM架构在高性能计算领域的潜力。

## CISC vs RISC
如何设计指令集，才能让CPU运行得更快？通过对大量实际运行程序的统计分析，发现了一个被称为”二八定理“的现象，即在程序中，大约80%的时间都在执行指令集中大约20%的简单指令（如数据加载、存储、加法等）。而那些复杂、强大的指令，虽然单条指令能完成更多工作，但使用频率极低，并且其复杂的译码和执行逻辑，反而可能拖慢整个CPU的运算。

这一发现直接催生了两种截然不同的指令集设计思路：精简指令集（RISC, Reduced Instruction Set Computer）与复杂指令集（CISC, Complex Instruction Set Computer）。
* CISC：核心理念是通过增强单条指令的能力，是CPU指令更接近高级语言语句，从而减少编程所需的指令条数，以降低汇编语言编程难度。代表是 x86 架构
* RISC：核心理念是化繁为简，只保留那些使用频率高的简单指令，并让所有指令在固定的时钟周期内完成。编译器需要翻译成多条RISC指令，翻译工作加重。代表是 ARM 架构

RISC与CISC的争论并非一场你死我活的战争，而是一场互相借鉴的技术演进。

今天的x86指令集架构，可以被看作是”披着CISC外衣的RISC“，它对外保持指令集的兼容性，以兼容原有的庞大的软件生态，对内则采用RISC的设计思想，以追求极致的性能。反过来，现在RISC处理器，为了应对更复杂的应用场景，也适当引入了一些更复杂的指令。

## CPU指令格式
一条典型的机器指令，主要包含两个部分：操作码和操作数。
* 操作码：指令要执行的操作类型，比如 ADD/SUB/LOAD/STORE/JUMP 等
* 操作数：执行操作时所需要的数据或其来源地址，回答了对谁进行操作的问题，一个指令通常包含零个、一个或多个操作数。

> 为方便理解，并未使用二进制编码，而是使用了CPU指令对应的汇编语言

操作数可以是
* 直接数据：指令本身包含了需要参与运算的数值
* 寄存器编号：指明数据存放在哪个寄存器中
* 内存地址：指明数据存放在内存的哪个位置
* IO端口地址

按照指令的字节长度，分为不定长指令和定长指令
* 计算机早期：受限于硬件水平，指令格式相对简单，往往采用定长指令，比如所有指令都是32位，定长指令极大的简化了CPU的控制逻辑，电路逻辑简单，译码速度快，缺点是不够灵活，对于简单的指令也会占用32位的完整空间，造成一定的浪费
* CISC架构：普遍采用变长指令，一条x86指令的长度可以从1字节到15字节不等，设计灵活，可以根据操作的需要组合出最紧凑的指令形式，但是以牺牲CPU复杂度为代价的，对于变长指令，CPU在取指阶段无法预知下一条指令的起始位置，必须首先解码出第一条指令的长度，才能找到第二条指令的开始，增加了逻辑电路的复杂性
* RISC架构：指令长度是固定的，通常是32位，而当今x86仍然选择变长指令是历史的原因，源于其向下兼容的沉重包袱

## 寄存器和寻址
如果说内存（RAM）是一个巨大的仓库，里面堆满了数据和程序，那么CPU内部的寄存器就是CPU工作台上的几个“托盘”。CPU几乎所有的运算和处理，都必须先将数据从“仓库”（内存）搬到自己手边的“托盘”（寄存器）上才能进行。

为什么需要寄存器？速度！寄存器由触发器构成，直接位于CPU内部，其访问速度极快，通常是纳秒级别，而访问内存则需要通过总线，速度要慢上百倍甚至更多。如果CPU每次计算都直接去内存中取数据，其效率将大打折扣。因此，寄存器充当了高速缓存的作用，是CPU高效运行必不可少的“伙伴”。

寄存器分为：通用寄存器、段寄存器、标志寄存器、指令指针（IP/EIP/RIP）

通用寄存器
* AX：累加器，执行算术运算的核心
* BX：基址寄存器，被用来存放访问内存时的基地址
* CX：计数器，专为循环设计，常用于循环计数
* DX：数据寄存器，常用于存放数据，也用于IO操作时提供端口地址

寻址方式
* 立即寻址：操作数直接包含在指令中
* 寄存器寻址：操作数位于CPU寄存器中，地址码部分就是一个寄存器编号
* 直接寻址：指令中直接给出了操作数所在的内存地址
* 寄存器间接寻址：操作数的内存地址存放在一个寄存器中，这个寄存器就像一个C语言中的指针
* 基址变址寻址：操作数地址由一个基址寄存器和一个变址寄存器的值相加得到，这几乎是为访问数组和结构体量身定做的模式
* 带比例的变址寻址：寻址地址进一步增强，变址寄存器的值可以乘以一个比例因子，这对于元素大小为2、4、8字节的数组方式带来了极大的遍历
* 相对寻址：通常用于跳转指令，操作数的地址是当前的指令寄存器EIP/RIP值加上一个偏移量，汇编器会自动计算出从JMP指令的下一条指令到label处的偏移量

## 汇编语言指令
为什么有时候看到的汇编语言不一样呢？

汇编语言并非一种单一的语言，而是一个庞大的家族。因为指令集有不同的架构，不同指令集所包含的指令的是不同的。同时即便在同一个指令集中，也存在不同的语法风格。最典型的x86架构下Inter语法和AT&T语法，它们指令相同，但操作数顺序，符号使用很大差别。

CPU指令或汇编语言指令到底有多少条？
* CPU指令和汇编语言指令是一一对应的，因此，有多少条CPU指令就有多少条汇编语言指令。在不同的指令集中，CPU指令的个数也是不同的。
* 对于RISC指令集，其设计哲学是保持核心指令精简。ARM核心指令集大约只有数百条。它通过可选的指令集扩展（如NEON用于SIMD，Cryptography用于加密）来增加功能，保持了核心的简洁与高性能。
* 对于CISC指令集，其代表x86/x86-64指令集是数十年演进的产物，核心指令有数百条，但若算上所有扩展（如MMX、SSE、AVX、AES-NI等），总数可达数千条。

不管是CISC还是RISC，其核心的指令不包括扩展，也就几百条，再按照2-8原则，其实，常用的也就数十条，接下来，我们就来看下，这些常用的指令。

主要指令分类
* 数据传输指令
  * MOV：将数据从源操作复制到目标操作数
  * PUSH/POP：专门用于管理后进先出的栈结构，用于函数调用
* 算术运算指令：ADD/SUB/MUL/DIV/INC/DEC
* 逻辑运算指令
  * 位逻辑运算：AND/OR/XOR/NOT
  * 移位运算：SHL/SHR
* 控制流指令
  * 无条件跳转：JMP
  * 条件跳转：CMP/JE/JG/JNE
  * 子程序调用：CALL/RET
* 处理器控制指令
  * NOP：空操作，但会消耗一个时钟周期，用于精确延时、代码对齐以提升取指效率
  * HLT：暂停操作，使CPU进入休眠状态，知道硬件中断到来
  * STI：中断控制，开中断，允许CPU响应可屏蔽硬件中断
  * CLI：中断控制，关中断，暂时禁止响应。操作系统在执行关键代码（如修改内核数据结构）前关中断，防止被意外打断，确保操作的原子性

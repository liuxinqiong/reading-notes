## 主存储器
存储器层级结构：寄存器、高速缓存、内存、硬盘。

存储器层级的理论基础是局部性原理，包括时间局部性和空间局部性。
* 时间局部性：如果某个数据被访问，那么它在不久的将来很可能再次被访问
* 空间局部性：如果某个内存位置被访问，那么它相邻的位置也可能很快被访问

基于这一原理，存储器层次结构呈现出金字塔式的布局，金字塔顶是寄存器，往下依次是高速缓存、内存、硬盘。
- 寄存器：位于CPU内部，是最快的存储介质，存取速度仅需1个时钟周期，但数量极少，通常只有几百到几千字节，成本最高。寄存器为CPU提供当前正在执行的指令所直接操作的数据。
- 高速缓存：分为L1、L2和L3三级缓存。L1缓存最接近CPU核心，通常为几十KB到几百KB，存取仅需几个时钟周期；L2缓存容量较大，通常为几百KB到数MB，但有2-10倍于L1的延迟；L3缓存为多个CPU核心共享，容量可达数十MB，速度较L2更慢但远快于主内存。
- 内存：也叫做主存储器，存取需要几百个时钟周期，容量通常为数GB到数TB，是程序运行时的主要工作区域。
- 硬盘：跟光盘等存储设备一起，统称为辅助存储器，其中，硬盘一般包括固态硬盘（SSD）和机械硬盘（HDD），存取需要成千上万个时钟周期，但容量极为庞大，用于长期存储数据。

寄存器是触发器（晶体管）构成的，通过触发器来存储二进制位，那么内存又是通过什么器件来存储二进制位的呢？这里分为动态随机存取存储器（DRAM）和静态随机存取存储器（SRAM）。其中内存通过DRAM实现，CPU的高速缓存通过SRAM实现。

DRAM的每个存储单元相较于触发器要简单很多，由一个晶体管和一个电容组成，利用电容上的电荷来存储数据，电容充满电代表1，放完电代表0。这种简单结构带来了显著的优点：晶体管少，成本低，使得制造大容量内存成为可能。但简洁性也带来了相应的挑战：电容会自然漏电，导致存储的电荷逐渐流失，这意味着必须定期刷新每个存储单元中的数据，即读取每个单元的数据并重新写入；同时，因电容充电较慢，DRAM访问速度也相对较慢，通常需要几十纳秒。

SRAM的每个存储单元由六个晶体管组成一个双稳态电路。只要持续供电，这个电路就能无限期地保持其状态，无需额外的刷新操作。因为只有晶体管，它访问速度极快，通常只需几纳秒即可完成数据读写，比DRAM快数倍甚至数十倍。然而，相较于DRAM，SRAM使用的晶体管更多，电路更复杂，这导致每个存储单元占用较大的芯片面积，使得在相同成本下能够实现的容量有限，功耗也相对较高。因此，SRAM不适合作为大容量的主存储器，而是主要用于CPU内部的高速缓存。

从逻辑层面或者软件层面，我们可以将内存抽象为一个存储二进制数据的巨大数组。为了便于寻址与管理，计算机将一个字节8 bits定义为可独立寻址的逻辑上的最小单元，并为数组中的每一个字节单元赋予一个唯一的物理地址。

逻辑上那个巨大的字节数组，在物理上是通过通道、Rank、DRAM芯片、Bank（存储阵列）等多级结构来实现的。
* 通道：一般主板上有多个插糟，这不仅是为了增加内存大小，还是提升性能的精巧设计（多通道技术），常见的通道数有双通道、四通道、八通道，通道数是有CPU和主板内存插糟共同决定的，普通的小飞机CPU和主板通常最高支持双通道，服务级别的一般支持四通道或八通道。
* Rank：一个Rank是一个由多个DRAM芯片组成的芯片组，这些芯片协同工作，共同响应一次内存控制器发出的读写命令。多少个芯片组成一个Rank取决的内存的位宽和单个芯片的位宽。在现在计算机的64位系统中，一个Rank必须能在一次操作中提供或接收64位数据。
* 芯片：是数据存储的物理载体，Rank是逻辑概念，而DRAM芯片是构成Rank的物理实体。每个芯片都通过金手指上的导线与内存控制器相连，负责存储总数据的一部分，例如在一个由8个8位芯片组成的Rank，当你读取一个64位数据时，每个芯片会同时贡献出自己那8位，最终在内存控制器处拼凑出一个完整的数据。
* Bank：一颗DRAM芯片内部通常包含多个（如8个、16个）独立的Bank。每一个Bank的核心，都是一个由行和列组成的二维网格，这就是存储阵列。阵列的每个交叉点就是一个物理存储单元，由一个晶体管和一个电容器构成。电容是否储存电荷代表存储的是1还是0，晶体管则充当开关，控制访问。

Bank的读写操作会经历行激活、读写、预充电三个步骤。
- 行激活：内存控制器首先发送一个行地址，并发出RAS信号。目标Bank中对应的整行（通常包含数千个存储单元）会被打开，它们电容上的电荷值被读取并放大，整行数据被暂存在一个称为行缓冲区的临时区域。
- 读写：接着，内存控制器发送列地址，并发出CAS信号。这时，从行缓冲区这个“记事本”中，根据列地址挑选出特定的一个或一组数据（取决于数据位宽），进行读取或写入操作。
- 预充电：操作完成后，必须将打开的行关闭，这一过程称为预充电。行缓冲区中的数据会被写回原来的存储单元（因为电路特点，读取是破坏性的），为下一次激活操作做好准备。

Bank是实现并行操作的关键。相对于CPU来说，是比较慢速的，CPU发号指令之后，都在等着数据。为了避免等待，那么，就安排了多个Bank同时为CPU提供服务，尽管同一时刻只会有一个Rank在被CPU读写数据，但是，其他Rank可以进行行激活和预充电等无需CPU参与的工作，这样整体吞吐量就提高了。

因此，看似非常简单的一次内存访问，要经历层层定位：
1. 选择通道：内存控制器决定使用哪个内存通道
2. 选择RANK：通过片选信号激活目标RANK
3. 选择芯片：该RANK中的所有芯片同时被激活
4. 选择BANK：在每个芯片内部选择目标BANK
5. 激活行：在选定的BANK中打开整行数据
6. 读取列：从激活的行中选择特定列的数据
7. 数据汇集：所有芯片的数据通过金手指汇合，形成完整的64位数据。

一个简单的内存访问，要经过层层定位，产生对应的使能信号，还是比较复杂的，这完全可以封装成一个独立的模块，以封装其复杂性。因此，就有了内存控制器这个组件。当然，内存控制器的功能远不止有地址解码。内存控制器的主要功能包括：
- 地址解码：将CPU发出的内存地址转换为物理位置，包括通道、RANK、芯片、BANK、行和列的选择。
- 命令调度：对内存访问命令进行重新排序和优化，以减少冲突和等待时间，提高内存带宽利用率。
- 刷新管理：定期对DRAM单元进行刷新操作，防止数据因电容器漏电而丢失。
- 功耗管理：根据系统负载动态调整内存的工作状态，平衡性能与功耗。
- 错误检测与纠正：支持ECC（错误纠正码）功能，检测并纠正内存中的软错误，提高系统可靠性。

实际上，内存控制器的调度算法对系统性能有显著影响。优秀的控制器能够在复杂的内存访问模式中找出最优的执行顺序，避免资源冲突，减少等待时间，最大化内存带宽的利用率。

## 硬盘存储
与内存的电子存储机制不同，**机械硬盘利用磁性材料的物理特性实现数据存储**。磁性介质在断点后仍能保持磁化状态，确保了数据的长期保存。

机械硬盘读写数据的过程基于电磁转换原理。
* 写数据时，写磁头将表示二进制数据的电信号转换为磁场变化，改变磁性介质的磁化方向
* 读数据时，读磁头通过感应盘片旋转时产生的磁场变化，输出相应的电压信号，经过方法和解析后还原存储的数据

**盘片是数据的存储载体，采用铝合金或玻璃基板，表面覆盖均匀的磁性介质，直径通常为3.5英寸或2.5英寸**。多个盘片平行安装在主轴电机上，构成主要的存储空间。主轴电机驱动盘片高速旋转，转速范围从5400r/min到15000r/min。较高的转速带来更快的数据访问速度，但同时增加功耗、发热和运行噪音。

**磁道是盘片上的同心圆轨迹，数据就存储在这些磁道上。每个磁道又被划分为若干扇区，扇区是硬盘最小的物理存储单元，通常每个扇区可存储512字节或4096字节的数据**。

磁头组件是硬盘中最精密的部件。**每个盘面对应一个磁头**，所有磁头同步移动（为什么？待会解释）。在读写操作时，磁头以极低的高度悬浮在盘片上方，飞行高度不足10纳米，悬浮速度却接近200公里/小时。这种设计确保磁头能够准确感应磁场变化，同时避免与盘面直接接触。硬盘内部对环境洁净度要求极高，微米级的灰尘颗粒都可能造成数据丢失或设备损坏。因此硬盘采用完全密封结构，禁止用户自行打开外壳。

这里我们解释一下：所有磁头为什么是同步移动的？

因为所有的磁头臂都固定在同一根支架上，因此当需要访问数据时，整个磁头组件会作为一个整体一起移动，将所有磁头同时定位到各自盘片的相同半径位置，即同一个柱面，**注意柱面是一个逻辑概念，并不是真正存在的物理组件**。

硬盘的控制电路通过电子开关，**从已经就位的这一排磁头中，选择一个特定的磁头（即选择某一个盘面）来激活，进行读取或写入。其他位于同一柱面上的磁头则处于非激活状态，不进行数据的读取或写入**。

为什么这样设计？关键在于成本和复杂性。如果为每个磁头都设计独立的驱动臂和定位系统，硬盘的机械结构将变得极其复杂、昂贵且笨重，而且难以保证所有磁头的精确同步。而将所有的磁头固定在一起移动，大大简化了机械设计和控制逻辑。

HHD工作原理
* 接受指令：指令最终被转换为具体的CHS参数：在哪个柱面（磁道）、哪个磁头（盘面）、从哪个扇区开始。
* 定位寻址：主控芯片驱动电机，带动整个磁头臂组件径向（沿直径方向）移动，将所有磁头从当前位置静准备的定位到目标数据所在的柱面上方。这个过程所花费的时间就是寻道时间。磁头就位后，需要等待盘片在高速旋转下，将目标扇区转到磁头的正下方，这个等待时间就是旋转延迟。
* 数据传输：定位完成后，真正的数据读写操作就开始了。

写入数据的过程：控制电路确保选定的磁头是写磁头，并准备好要写入的数字信号（一系列0和1）。当目标扇区旋转到写磁头下方时，电路将数据信号转换成不同方向的电流，输送给写磁头。电流通过写磁头线圈，产生精确变化的磁场。这个磁场会瞬间磁化其正下方盘片磁性介质中微小区域的磁颗粒方向。例如，北极朝上代表“1”，南极朝上代表“0”。这样，数据就被物理地“刻录”在了盘片上。

读取数据的过程：控制电路激活对应的读磁头。当存储着数据的扇区旋转到读磁头下方时，盘片上磁颗粒产生的微小磁场会使读磁头的电阻发生改变。这种电阻变化被探测电路转换为微弱且变化的电压信号。这个微弱的电压信号经过前置放大器放大并消除噪音，最终被解析还原成原始的二进制数据（0和1）。

从上述读写过程，我们可以发现，在硬盘性能表现中，顺序读写和随机读写有着天壤之别。顺序读写是指访问硬盘上连续存储的数据，磁头只需极少的移动即可完成大块数据的读写，速度通常可达100-200MB/s。而随机读写需要磁头在不同位置间频繁移动，性能大幅下降，可能只有1-2MB/s。

这种性能差异对软件开发有着深远影响。数据库设计者通过顺序组织数据来减少随机I/O；文件系统开发者设计日志结构或索引组织来优化小文件存储；操作系统则利用预读技术和缓存策略来掩盖硬盘访问延迟。理解硬盘的访问特性，有助于开发人员编写出更高效的I/O密集型应用程序。

其实，为了提高读写性能，机械硬盘往往在内部会集成一颗独立的DRAM芯片作为缓存。

早期硬盘缓存很小，只有几MB。随着技术的发展，现代普通机械硬盘的缓存容量通常在64MB到256MB之间。一些高端的企业级硬盘可能会达到512MB甚至1GB。缓存越大，对性能提升越有利。

读缓存的核心思想是“预判你的需求”，通过减少直接访问盘片的次数来提升读取效率。

当CPU请求数据时，硬盘控制器首先在高速的缓存中查找。如果数据已经在缓存里，就能立即返回，完全避免了耗时的机械寻道和旋转延迟。这被称为“缓存命中”。一次机械寻道可能需要数毫秒，而从缓存（DRAM）读取数据仅需纳秒级，大大提升了读的性能。

除此之外，基于“数据访问的空间局部性原理”（即程序很可能接下来会访问相邻的数据），当硬盘读取某个扇区时，它会顺势将后续的若干个扇区数据也提前读入缓存。如果程序接下来正好请求这些数据，就能直接从缓存中瞬间获取，性能得到巨大提升。比如，当你打开一张图片的开头部分时，硬盘可能已经将整张图片的数据都加载到了缓存中，确保你滚动浏览时无比流畅。

写缓存的核心思想是“对你撒谎”，它通过“延迟回写”的策略，创造了一种迅速写入的“幻觉”。

当操作系统要求写入数据时，硬盘会先将数据写入高速的缓存，然后立即向操作系统报告“写入完成”。此时，数据并未真正落到盘片上。之后，硬盘会在空闲时，才将缓存中的数据后台写入到最终的存储介质中。这种策略使得应用程序无需等待物理写入的实际完成，极大地提升了系统的响应速度和用户体验。除此之外，它还可以将多次零散的小写入合并成一次大的顺序写入，提高硬盘的吞吐量。

不过，写缓存最大的风险是数据丢失。如果在硬盘报告“写入完成”但数据还未实际落盘时，发生系统断电或崩溃，那么这些在缓存中的数据就会永久丢失。因此，为了保护数据，硬盘提供了刷新缓存的功能接口，可以由操作系统或应用程序主动调用去刷新缓存。而且，**企业级和许多消费级硬盘在电路板上还设计了钽电容。在意外断电时，电容储存的电量足以让硬盘完成“临终操作”，即将DRAM缓存中的所有数据紧急写入物理介质，从而保证数据安全**。

是否存在更先进的数据存储方式？答案是肯定的，随着半导体技术的飞速发展，固态硬盘已经决定，成为更先进、更快速的持久化存储器。

CPU Cache、内存都是基于晶体管实现的，它们只有在通电情况下才能工作，断电之后数据全部丢失。其实，SSD也是基于晶体管实现的，但它可以在断电时仍然保存数据，不同的地方在于，**它使用了一种特殊的晶体管：浮栅晶体管。“浮栅”就是SSD断电之后不丢失数据的奥秘。浮栅晶体管支持在通电的情况下将电子注入或移出被绝缘层隔离的浮栅，在断电的情况下，浮栅又能有效地“囚禁”电子，从而长期保持所代表的数据状态（0或1）**。

与HDD依靠磁头在盘片上读写数据的机制完全不同，SSD这种纯电子化的操作方式，让其访问速度达到了微秒级（几十到几百微秒），比传统HDD（通常为几毫秒到十几毫秒）快了数十倍到数百倍。特别是在随机读写方面，高性能SSD能够达到惊人的100,000 IOPS（每秒输入输出操作数），而传统HDD通常只能达到100-200 IOPS。这种性能差距在我们的日常使用中表现得淋漓尽致：配备SSD的计算机可以在十几秒内完成启动，应用程序几乎是瞬间打开，文件传输速度更是快得令人惊叹。

然而，传统HDD并非没有存在的价值。在成本容量比这个关键指标上，HDD依然保持着明显优势。目前，每GB的存储成本，HDD大约只有SSD的1/5到1/10。这个价格差异使得HDD在大容量数据存储场景中仍然不可替代。想象一下，对于一个需要存储数十TB数据的企业或研究机构来说，选择HDD可以节省大量成本。此外，**在数据长期保存方面，HDD的磁性存储比SSD的电荷存储具有更好的数据保持特性，这为重要数据的长期归档提供了更可靠的选择**。

正是基于这些特点，现代计算机系统发展出了混合使用策略。**我们可以将SSD用作系统盘，存储操作系统和常用应用程序；同时使用HDD作为数据盘，存储那些容量较大但不常访问的文档、媒体文件和备份数据**。这种分层存储架构让SSD和HDD各自发挥所长，在性能和成本之间找到完美的平衡点。

## 高速缓存
CPU Cache 并不是单一的一块，而是通常分为三级：L1、L2、L3 Cache。当我们拆开电脑，可以看到放行的 CPU 其实是一个封装好的模块。里面最核心的是一片正方形的硅晶片，这就是芯片。所有的核心和缓存都密密麻麻地集成在这片小小的芯片上，就包括L1，L2和L3 Cache。
* L1 Cache：在每个CPU核心的内部，是核心不可分割的一部分，每个核心独占自己的L1缓存，容量很小，通常在32KB到64KB之间，由于离核心的执行单元和寄存器最近，物理距离极短，信号延迟最小，因此速度最快。L1 Cache通常被划分为L1指令缓存（IL1）和L1数据缓存（DL1），分别用于存放指令和数据。
* L2 Cache：也在CPU上，通常位于每个CPU核心的旁边或附近，但与L1相比，与核心距离稍远一些。在现在CPU设计中，L2 Cache同样是每个核心独占的，容量通常在几百KB到1MB之间，不在严格区分指令和数据，而是混合存放
* L3 Cache：也在CPU上，但通常被放在所有CPU核心的周围或它们之间的空白区域，由芯片上所有CPU核心共享，容量最大，现在消费级CPU可到几十MB，但速度也最慢。它的作用是作为整个CPU芯片的最后一道缓存防线，协调不同核心之间的数据共享，避免它们都去访问速度更慢的内存。

为什么不早一个大容量的L1呢？
* 一个大容量的SRAM阵列，其对角线距离会很长，信号从一段传到另一端需要更多时间，访问延迟会急剧增加。L1之所以能保持2-4个时钟周期的超低延迟，正是因为它小，且紧贴核心旁边
* 缓存中查找需要数据，需要一定的查找算法，对一个大容量的L1进行数据查找，需要极其复杂和庞大的比较器电路，进一步增加了延迟和功耗
* 因此一个巨大的L1，其速度必然会下降，就会退化成一个慢速的缓存，这就失去了它存在的根本意义

缓存的基本单元：Cache Line 也常被成为 Cache Block，是CPU在Cache和主内存之间传输数据的最小单位，它不是一个个单独的字节，而是一个连续的、固定大小的数据块。现在计算机中，一个典型的Cache Line是64字节。

了解了Cache Line的由来，我们再来看下，一个Cache Line包含哪些部分。
- 数据块：这是Cache Line的主体，存放着从主内存中拷贝过来的实际数据，大小通常为64字节。
- 标签（Tag）：这是该Cache Line的“身份证”。它记录了这64字节数据来自于主内存中的哪个地址范围。当CPU查询一个地址时，就是通过比较Tag来确认这个Cache Line里是否正好存放着它想要的数据。
- 有效位：这是一个1位的标志，用于表明当前缓存行中的数据是否有效。当系统刚启动时，所有缓存行的有效位都是0（无效）。当缓存行被加载了有效数据后，有效位会被设置为1。如果缓存行被标记为无效，那么当CPU访问该行时就会发生缓存未命中，即使Tag匹配也不行。
- 其他状态位：在多核处理器中，为了维护缓存一致性，每个缓存行还需要一些状态位来实现缓存一致性协议（如MESI协议）。MESI协议中每个缓存行可能有四种状态：修改（M）、独占（E）、共享（S）和无效（I），因此需要2个位来存储这些状态。

需要一套规则来决定“内存中的某块数据，可以放在Cache的哪个位置”，主要有如下三种映射方式
* 直接映射：最简单的方式，把内存分成若干个与Cache行大小相同的块，然后通过一个简单的取模运算，来决定一块内存数据只能放在Cache中唯一的一个特定位置。优点是硬件实现简单，查找速度极快。CPU只需要根据地址计算出索引，直接去那个位置查看即可。缺点是冲突严重，如果两个经常访问的内存地址恰好映射到同一个Cache行，它们就会不停的互相踢出对方，导致缓存频繁失效，即使Cache其他位置是空的也无济于事。
* 全相联映射：任何一块内存数据可以被放置在Cache中任意一个空闲位置。优点是非常灵活，最大限度地利用了Cache空间，缺点是查找成本极高。
* 组相联映射：在硬件复杂度和冲突率之间取得平衡的缓存组织结构，现代CPU普遍采用此结构。

缓存写回策略
* 写直达：数据会同时被写入Cache和主内存
* 写回：数据只写入Cache，而不会立即更新内存。同时硬件会将被修改过的Cache行标记为“脏”，只有当这个脏行因为空间不足而替换出Cache时，才会将其写回内存。这样做极大地提升了写操作的性能，减少了内存访问次数和总线带宽占用

缓存一致性问题”写回策略在单核CPU下工作良好，但在多核处理器中，新的挑战出现了：同一个数据可能会被多个核心的Cache同时缓存，此时便会出现多核环境下的缓存一致性问题。

为了解决这个问题，计算机制造商们设计了一套复杂的协议，最著名的是MESI协议（以其四种状态的首字母命名）。MESI协议为每个Cache行维护一个状态位，它可以是以下四种状态之一：
- M 修改：该行已被当前核心修改（“脏”），与内存中的数据不一致。这是该数据唯一的最新副本。
- E 独占：该行只被当前核心缓存，且与内存中的数据一致。核心可以放心地修改它，之后状态会变为M。
- S 共享：该行可能被多个核心缓存，且所有缓存中的数据都与内存一致。核心可以读取它，但不能直接修改。
- I 无效：该行中的数据是过时的、无效的，不能使用。

MESI协议通过核心之间的“窥探”机制来工作。每个核心都“监听”总线上的所有缓存事务。例如，当一个核心想要写入一个处于S状态的缓存行时，它必须在总线上广播一个“无效化”消息，让所有其他核心将它们缓存中的该行副本标记为I，然后它才能写入，并将自己的状态变为M。当一个核心想要读取一个不在自己缓存中的数据时，它会发起一个“读请求”。如果另一个核心有这个数据的M状态副本，该核心会拦截这个请求，将它的“脏”数据写回内存，并将状态变为S，然后请求者核心才能从内存读到最新数据。

通过这一系列精细的状态转换和消息通信，MESI协议确保了在所有核心的眼中，对同一个内存地址的读写顺序是一致的，从而维护了多核系统的正确运行。

缓存伪共享问题，前置知识
* Cache Line是数据交换的基本单位（通常是64字节）
* 多核缓存一致性协议（如MESI）以Cache Line位粒度来维护一致性

假设我们有一个结构体，里面有两个频繁被写的计数器
```c++
struct Data {
    int counter_a;
    int counter_b;
}
```

在内存中，counter_a和counter_b是紧挨着存放的。由于它们体积很小，有很大的概率会位于同一个Cache Line中。现在，我们将这个结构体的实例交给两个分别运行在CPU核心A和核心B上的线程：
- 线程A只关心counter_a，它会将包含counter_a的整个Cache Line加载到核心A的L1缓存中。
- 线程B只关心counter_b，它也会将包含counter_b的同一个Cache Line加载到核心B的L1缓存中。

此时，一切正常，Cache Line在两个核心中可能处于共享（S）状态。

如果线程A要增加counter_a，由于它需要写入，根据MESI协议，它必须获取该Cache Line的独占（E）或修改（M）权限。为了做到这一点，核心A必须在总线上发送一个“无效化（Invalidate）”消息。核心B“窥探”到这个消息，于是将自己缓存中的这个Cache Line标记为无效（I）。线程A成功写入counter_a，并将它的Cache Line状态变为M。

紧接着，线程B要增加counter_b，它发现自己的Cache Line已经是无效状态。于是，线程B必须发起一次缓存未命中，从核心A的缓存或内存中重新读取这个（已经被线程A修改过的）Cache Line。随后，线程B成功写入counter_b，这又会导致它发送无效化消息，使核心A的缓存失效...如此循环往复。

问题的关键在于：这两个线程在逻辑上并没有共享数据！线程A并不操作counter_b，线程B也不操作counter_a。但它们却因为住在同一个“Cache Line公寓”里，导致一方装修（写入），另一方就被迫要重新办理入住手续（缓存未命中）。这种不必要的缓存行无效化和传输，会耗尽宝贵的内存总线带宽，并显著增加缓存未命中率，导致程序性能随着线程数增加不升反降，而且问题极难被发现。

其实，解决伪共享的思路也不难。既然矛盾源于“合租”，那就让它们“分开住”。我们通过内存对齐和缓存行填充技术，强制让两个高度竞争的变量位于不同的Cache Line上。如下所示，在64字节Cache Line的系统上，counter_a占据前4字节，后面有60字节的填充，这使得counter_b几乎肯定会从第64字节开始，从而进入一个新的Cache Line。
```c++
struct PaddedData {
    int counter_a;
    char padding[60]; // 手动填充约60字节，确保counter_b在下一个Cache Line
    int counter_b;
}
```

除了手动对齐外，现代编译器提供了更加优雅的属性来实现对齐，如下所示，这样无论结构体如何被使用，counter_a和counter_b的起始地址都必定是64的背书，即各自独占一个Cache Line的起始位置，从根本上度解决了伪共享、
```
// c++11及以后，可以使用标准化的 alignas 关键字
struct AlignedData {
    alignas(64) int counter_a;
    alignas(64) int counter_b;
}

// Java8+中，使用 @Contented 注解，需要添加JVM参数，-XX:-RestrictContended
class Data {
    @sun.misc.Contended
    public int counter_a;

    @sun.misc.Contended
    public int counter_b;
}
```

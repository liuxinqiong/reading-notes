# IP地址
在互联网的世界里，数据包从你的电脑出发，穿越千山万水到达目标服务器，同样需要一套精密的地址系统。这就是 IP 地址。

你的电脑网卡上其实已经有一个与生俱来的标识了，那就是MAC地址。MAC地址，全称媒体访问控制地址，也叫做物理地址或硬件地址。他是有网络设备制造商在生产时烧录在网卡上的，全球唯一，通常表示为12位16进制数，比如00-16-EA-3C-40。形象的说MAC地址就如同身份证号码，伴随设备终生，不可更改。

既然每个网卡都有一个身份证号，为什么还需要再发明一套IP地址呢？

**第一，MAC地址是“物理的”，IP地址是“逻辑的”**。 MAC地址就像你的身份证号，生下来就有，永远不会变。但如果搬家了，你的身份证号能告诉别人你现在住在哪里吗？不能。IP地址就像你的“现住址”，它会随着你接入不同的网络而变化。当你带着笔记本电脑从公司回到家，你的MAC地址没变，但IP地址变了。网络需要这种“逻辑地址”来反映设备当前的网络位置，而不是它永恒不变的“身份”。

**第二，MAC地址是“平面的”，IP地址是“层级的”**。 MAC地址的结构是扁平的，它只告诉“我是谁”，不告诉“我在哪儿”。所有MAC地址之间没有任何层级关系，就像全世界的人只凭身份证号相互通信，你根本不知道这个人住在地球哪个角落，该怎么把信送到他手上。而IP地址是分层的，它包含了“网络号”和“主机号”两部分，就像邮政编码加门牌号，可以指引数据包一步步找到目的地。

**第三，MAC地址在第二层工作，IP地址在第三层工作**。 在OSI模型中，MAC地址应用于数据链路层，负责在同一个局域网内将数据帧从一个节点传递到另一个节点；而IP地址应用于网络层，负责将数据包从一个网络传递到另一个网络。两者的分工是：IP地址负责跨网络的“长途运输”，MAC地址负责到达目的局域网后，在“最后一公里”，交换机通过MAC地址把数据准确交到目标主机手上。

IP 分类编址

IP 包含网络号和主机号两部分，为什么做此区分呢，因为路由器需要根据网络进行转发，而不是记住世界上每一台机器，否则路由器维护映射表会大的离谱。与此同时还解决了另一个问题，发送发可以判断目标是不是和自己同一个网络。

比如你的电脑 IP: 192.168.1.10/24 你要访问 192.168.1.25，计算网络号：
```shell
192.168.1.10 & 255.255.255.0
= 192.168.1.0

192.168.1.25 & 255.255.255.0
= 192.168.1.0
```

网络号相同，所以电脑就能知道跟自己是同一个局域网，不用找路由器，于是自己通过 ARP 找到 192.168.1.25 对应的 MAC 地址，然后发送以太网帧。

在互联网莽荒时代，设计者最初的构想很直接：既然地址需要区分网络号和主机号，那就定几个固定的标准吧。他们把 IP 地址（特指 IPv4 地址，由 32 为二进制组成）分成了五类：A/B/C/D/E。其中 A/B/C 是用于普通网络通信的主力，D/E则另有用途。

A类地址：为超大型网络设计

A类地址的特点是用第一个8位（也就是第一段数字）表示网络号，而且规定网络号的最高位必须是0。这意味着全世界只有126个A类网络（网络号从1到126，0和127被保留，有特殊用途），但每个网络里能容纳高达1600多万（主机号占24位，2^24-2，主机号全0或全1的不能用）台设备。

B类地址：为中等规模网络设计

B类地址用前两个8位表示网络号，且前两位固定为“10”。这允许有1.6万（2^14）多个B类网络，每个网络能容纳6.5万多（主机号占16位，2^16-2，主机号全0或全1的不能用）台设备。

C类地址：为小型网络设计

C类地址用前三个8位表示网络号，且前三位固定为“110”。这意味着有200多万（2^21）个C类网络，但每个网络最多只能容纳254（主机号占8位，主机号全0或全1的不能用）台设备。

D类地址：用于组播通信

D类地址的前四位固定为“1110”，地址范围是224.0.0.0到239.255.255.255。D类地址不用于普通的“一对一”通信，而是用于“一对多”的组播。（注意：组播和待会提到的广播我们留在后面讲解）

E类地址：保留做实验用

E类地址的前四位固定为“1111”，地址范围是240.0.0.0到255.255.255.255。这类地址被保留起来，供实验或未来使用，从不分配给普通用户。

除了这五类地址，还有一些特殊的IP地址值得了解：网络地址（主机号全0，代表网络本身）、广播地址（主机号全1，代表网络中所有主机）、环回地址（127.0.0.0/8，用于本机测试，最常用的是127.0.0.1）等。

> 注意 D/E 两类就没有网络号+主机号的划分了，于此同时，巧妙的前缀固定位设计，使得彼此之间也不会出现冲突的情况。

上述固定网络号的方式已经不在使用了，而是使用无类域间路由 CIDR 方案，它彻底抛弃了 A/B/C 类的概念，不再使用固定的 8 位、16位、24位来划分网络号，允许网络号的长度是可以任意位数，从 13-27 位不等。采用了一种新的表示法：在IP地址后面加上斜杆和数字，比如 192.168.1.0/24，表示前 24 位是网络号

CIDR 解决了两个核心问题
* 按需分配，减少浪费。当一家公司需要 1000 个 IP 地址时，不再给他一个完整的 B 类提示，而是给他一块 /22 的地址，这个地址块正好包含 2 的 10 次方约 1000 个地址，完美匹配需求，几乎没有任何浪费。
* 路由聚合，减轻负担，CIDR 的另一个重要概念是超级组网，可以看做子网划分的逆过程。子网划分是把大网络切成小网络，而超级组网是把多个小网络聚合成一个大网络来路由。

CIDR 方式只是解决了分配方式的问题，但 43 亿的总量瓶颈依旧存在，能不能让多个设备共享一个公网 IP 呢？这就是私有 IP 地址和 NAT（网络地址转换）技术的用武之地。

设计者们预留了三段IP地址作为私有地址，专门用于局域网内部使用，不会分配出去：
* A类私有地址：10.0.0.0/8，范围是10.0.0.0 ~ 10.255.255.255
* B类私有地址：172.16.0.0/12，范围是172.16.0.0 ~ 172.31.255.255
* C类私有地址：192.168.0.0/16，范围是192.168.0.0 ~ 192.168.255.255

这就是为什么你家里的电脑、手机通常都是192.168.x.x，公司内部网络可能是10.x.x.x或172.16.x.x。这些地址只能在局域网内部使用，互联网上的路由器看到这些地址，会直接丢弃数据包，因为它们不属于公网。

为什么这么设计？你想想，如果全世界每台计算机都需要一个全球唯一的公网IP，那IP地址早就枯竭一百次了。私有地址在不同的局域网之间是可以重复的。因此，有了私有地址后，一个局域网只需要为路由器分配一个公网地址，内的计算机分配私有地址就可以，而当它们需要访问互联网时，再由路由器统一“翻译”成公网IP出去。

这个“翻译”的过程，就是NAT（网络地址转换）技术。

NAT 和 CIDR 都是续命的方案，但无法从根本上解决 IPv4 地址枯竭问题。真正的终极方式是 IPv6。

IPv6 最核心的改变是把地址长度从 32  位扩展到 128 位。

## IP 协议
IP 协议，全称互联网协议，它定义了数据在网络中传输的基本单位：IP 数据包，以及这个数据包的格式。每一个从你设备发出的信息，最终都会被切割、打包成一个或多个 IP 数据包，在网络中传输。

IP 协议的设计思想：无连接、不可靠但尽力而为，

无连接可以理解成平时寄快递，不会专门为你建立一条通道，你只需要把地址填好交给快递员就行。IP协议也是这样，不关心你之前发了什么包，也不关心之后还会发什么包。每个IP数据包都是独立的，它只管根据包上的目的地址，把他扔给下一个路由器。这种方式的好处是，网络无需为任何一对通信双方维护状态，极大的简化了核心网络的设计，提高了处理效率。

我们再来看不可靠但尽力而为。这是IP协议最核心的思想。IP协议不保证数据包一定能送到，也不保证数据包一定按顺序送到，更不保证数据包在传输过程中不出错。它只承诺一点：我会尽我最大的努力，去尝试把这个数据包送到目的地。如果中途遇到任何问题，比如找不到路了，或者路由器负载太高，那就直接扔了。至于通知发件人“你的快递丢了”，那不是我的事，是其他协议的事（你应该也能猜到，是它的上层TCP协议来保证）。

这个设计听起来很“不负责任”，但它背后隐藏着一个深刻的思考：把复杂的问题留给网络的“边缘”去解决，让网络的“核心”尽可能简单高效。

什么意思呢？想象一下，如果我们要求整个互联网上的每一台路由器都必须保证数据的可靠传输，那路由器就得记住每个数据包的状态，得准备缓存来重传，得处理各种异常情况。这样一来，路由器会变得极其复杂和昂贵，还影响转发性能，而且随着网络规模的扩大，这种复杂度会指数级增长。

而IP协议的这个“傻瓜”式设计，把保证可靠传输的责任推给了上层，也就是传输层的TCP协议。让你的终端计算机负责这些糟心的事情，比如可能会因为丢包而重传，但网络中间的路由器们，则“无债一身轻”，只管专注地、高速地转发数据包。这种“核心简单，边缘复杂”的设计原则，不得不拍手称赞！

## IP 路由
发送的线路要经过多个路由器，路径也不是唯一的，怎么选择一条最合适的路由，整个过程就是 IP 路由。

任何一个路由器，都不知道数据包到达最终目的地的完整路径，它只知道两件事
* 我直接连着哪些网络？
* 通过我的邻居路由器，我能到达哪些网络？

路由器的任务，就是根据数据包上的“目的IP地址”，结合自己掌握的这点“地理知识”（也就是路由表），做出一个决定：为了让这个数据包离它的最终目的地更近一步，我应该把它从我的哪个端口转发出去？下一个接收它的路由器（下一跳）应该是谁？也就是说，路由器从来不关心最终目的地的具体坐标，它只关心“下一步”。

路由器如何做出下一站去哪的决策呢？靠的就是它的核心数据：路由表。

一条典型的路由表条目，主要包含以下几个关键信息：
* 目的网络地址：注意它不是“某个具体IP”，而是一个地址段。比如192.168.1.0/24。这意味着，所有发给192.168.1.x这个地址段里任何一台电脑的数据包，都可以参考这条路由规则。
* 下一跳/出端口：它告诉路由器：“如果想去上面那个网络，你应该把数据包从我的哪个端口送出去，或者直接交给哪个邻居路由器（下一跳）。”
* 路由优先级：有时候，去同一个目的地，可能有好几条路，那听谁的？这就需要有一个优先级。比如，自己直连的网络优先级最高，管理员手动配置的静态路由次之，动态路由可能优先级更低。
* 度量值：如果优先级相同，路由器就会比较“度量值”。这个值可以理解为“成本”或“距离”，可能是要经过的路由器个数（跳数），也可能是链路带宽、延迟等。路由器会选择度量值最小的那条路径。

当一个数据包到达路由器时，它会执行一个非常高效的查找算法：用数据包的目的IP地址，去路由表中进行最长前缀匹配，找到那个最精确的匹配条目，然后按照这条条目，把数据包从对应的端口转发给下一跳。如果找不到匹配的路由项，这个数据包就会被这台路由器丢弃。

那么，路由表里的信息是怎么来的呢？主要有两种方式：静态路由和动态路由。

静态路由指的是，网络管理员用手工的方式，一条条把路由信息敲进路由器里。它最大的优点是：简单、高效。但是，一旦网络拓扑发生变化，比如某条链路断了，你得手动登录路由器去修改路由表。对于大型、动态变化的网络来说，这简直就是一场噩梦。

动态路由协议 RIP、OSPF、BGP
* 距离矢量算法 RIP：简单理解为我听我的邻居说
* 链路状态算法 OSPF：简单理解为我亲自去探索，然后画张地图
* 路径矢量算法 BGP：在告诉别人我能去哪的时候，顺便把具体路径也告诉它

## 辅助协议
ARP 地址解析协议：给定一个 IP 地址，查出同一个局域网中对应的 MAC 地址。

ICMP 互联网控制报文协议，ICMP 报文填充在 IP 数据包的数据中，当 IP 头部里的协议字段值为 1 时，就表示 IP 包的数据里装的事 ICMP 报文，主要分为两类：差错报告报文和询问报文。

ICMP 两个经典应用
* ping：主机向目标服务器发送 ICMP 回送请求报文，服务器收到后回复 ICMP 回送应答。ping 会统计发了几个、收到几个，用了多长时间，直观的告诉你网络连通性和延迟
* traceroute：用于跟踪数据包从源到目的经过的路径

DHCP

现在我们来解决一个更日常的问题：你的电脑、手机、平板接入网络时，IP地址是怎么来的？

当然你可以手动配置：打开网络设置，填上IP地址、子网掩码、默认网关、DNS服务器。但这么做有几个问题：第一，太麻烦；第二，容易填错；第三，可能和别人冲突；第四，网络大了根本管不过来。这时候就需要DHCP（动态主机配置协议）出场了。

DHCP是一种让终端设备自动获取网络配置的协议。设备接入网络后，不需要人工干预，就能从DHCP服务器那里“领”到一套完整的网络参数，包括：IP地址、子网掩码、**默认网关（也就是路由器的IP地址）**、DNS服务器、租约期限。

DHCP采用客户端/服务器模式，使用UDP协议（客户端端口68，服务器端口67）。**对于家庭局域网来说，DHCP服务器就是运行在路由器里的一个服务软件**。当你登录路由器的管理后台（比如192.168.1.1），就可以看到“DHCP服务器”设置页面。

DHCP的工作流程包括DORA：Discover、Offer、Request、ACK四个阶段。

第一步：Discover（发现）

当设备第一次接入局域网时，它还没有IP地址，也不知道DHCP服务器在哪。于是它发送一个广播包：源IP是0.0.0.0，目的IP是255.255.255.255，内容大致是“谁是DHCP服务器？我需要一个IP地址”。

第二步：Offer（提供）

网络里的DHCP服务器收到这个广播后，从自己的地址池里挑一个空闲IP，连同其他配置参数（子网掩码、网关、DNS等），封装成Offer报文，回复给客户端。注意，这时IP只是“预留”，还没正式分配。

第三步：Request（请求）

客户端可能收到多个Offer（如果网络里有多个DHCP服务器，为什么可能会有多个，我们待会解释）。它会选择其中一个（通常是第一个到的），然后广播发送Request报文，明确告诉所有DHCP服务器：“我接受某某DHCP服务器的Offer，我要用那个IP。”这一步广播是为了让其他没被选中的DHCP服务器知道“你不用给我留着了，把IP收回吧”。

我们再解释下，为什么会有多个DHCP服务器？

在家庭局域网中，网络结构很简单：一台路由器，下面连着几十台设备。路由器上运行着一个DHCP服务，负责给所有设备分配IP。这时候确实只有一个DHCP服务器，你的设备只会收到一个Offer，但这只是最简单的情况。在稍微大一点的网络里，为了保证可靠性，网络管理员通常会部署两台（甚至更多）DHCP服务器。

第四步：ACK（确认）

被选中的DHCP服务器收到Request后，正式把这个IP标记为“已分配”，并回复ACK报文确认。客户端收到ACK，配置生效，可以正常上网了。

DHCP分配的IP地址是有租约期限的，不是永久的。这样设备下线后，DHCP服务器在对应的IP过期之后，可以重新分配给别的设备。当租约过了一半（50%）时，客户端会尝试向服务器续租；如果没成功，等租约过了87.5%时，客户端会继续二次续租；如果还不行，租约到期，IP被收回，设备就得重新走一遍DORA流程。
